# CLAUDE.md

Classic Arkanoid (Breakout) game. Unity `6000.5.6f1`, Universal Render Pipeline, new Input System.

Gameplay is strictly 2D (2D physics on the XY plane) but the visuals are 3D: bricks, paddle and walls are box meshes, the ball is a sphere, all with URP Lit materials (`Assets/Materials`), lit by the scene's directional light in front of a shadow-catching `Backdrop` plane at z 0.6. The walls use a generated tileable brick-masonry texture (`Assets/Textures/BrickWall.png`, grayscale so the material tint colors it) on custom box meshes (`Assets/Meshes`) authored at final size with world-unit UVs per face — a scaled stock cube would squeeze the texture into stripes on its small faces (end caps, tops). The wall transforms are unit-scale, so their `BoxCollider2D` sizes are set explicitly; the `WallSide`/`WallTop` materials both tile 1:1. The camera is perspective (FOV 50 at z −13.5, framing-equivalent to the old orthographic size 6). Bricks are tinted per instance via `MaterialPropertyBlock` (`Brick.SetColor`), and the crack overlay stays a `SpriteRenderer` child sitting just in front of the box's face.

The paddle has rounded corners: a rounded-rectangle prism mesh (`Assets/Meshes/Paddle.asset`, 2 × 0.4 × 0.5, corner radius 0.15, authored at final size so the transform is unit-scale) paired with a `BoxCollider2D` shrunk by the radius on every side (1.7 × 0.1) plus `edgeRadius: 0.15` — exactly the same rounded rectangle — so the ball's bounce reflects off the corner curve's true normal. `Ball.cs` applies its arcade paddle-bounce override only when the contact normal is straight up (flat-top hits); corner hits keep the engine's reflection.

There are four brick shapes, and each prefab's 2D collider matches its visual outline exactly so the ball reflects off the shape's true contact normal:

- `Brick.prefab` — the normal 1.5 × 0.5 box (scaled stock cube + `BoxCollider2D`).
- `HalfBrick.prefab` — a half-width 0.68 × 0.5 box; two of them plus the level's 0.14 gap fill one normal slot (2 × 0.68 + 0.14 = 1.5).
- `RoundedBrick.prefab` — full-size with corner radius 0.12: a rounded-rectangle prism mesh (`Assets/Meshes/BrickRounded.asset`, built by the same `BuildRoundedPrismMesh` as the paddle, unit-scale transform) with a 1.26 × 0.26 `BoxCollider2D` + `edgeRadius: 0.12`, so corner hits reflect off the curve.
- `RoundBrick.prefab` — a 0.5-diameter sphere (stock sphere at scale 0.5) with a `CircleCollider2D` (radius 0.5 × scale = 0.25 world), so hits deflect along the circle's radial normal. Its crack overlay child is scaled 0.7 (≈ inscribed square) to stay over the circular silhouette.

`GameManager.rowKinds` assigns a shape per row (currently Rounded / Normal / Half / Round / Normal, top to bottom); Half and Round rows spawn two bricks per slot at slot center ± 0.41 and half the row's points each. `PrefabFor` falls back to the normal brick if a variant prefab is unwired. All four prefabs share the white `Brick.mat` tinted per instance, the crack overlay child, and the same `Brick` component — hardness and points are set per spawn.

## Layout

- `Assets/Scripts/Paddle.cs` — keyboard paddle movement (`Keyboard.current`, arrows/A-D), clamped to the playfield.
- `Assets/Scripts/Ball.cs` — constant-speed ball with a `Damage` value (currently 1) read by bricks on impact. Kinematic and paddle-following while attached; dynamic after launch. `FixedUpdate` renormalizes velocity to `speed` and enforces a minimum vertical component so the ball can't get stuck bouncing horizontally. Paddle bounces off the flat top override the physics reflection with an angle based on where the ball hit the paddle; hits on the paddle's rounded corners (tilted contact normal) keep the engine's reflection off the curve.
- `Assets/Scripts/Brick.cs` — accumulates the ball's `Damage` per hit against its `Hardness` (1–3, set per row by `GameManager`); destroys itself and reports its `Points` to `GameManager` once damage reaches hardness, spawning falling `Debris` fragments in its color as it goes. While still alive it shows a crack overlay on the prefab's `Cracks` child renderer — light crack up to half damage, heavy crack beyond — from parallel arrays of sprite variants wired in by the editor setup script. On its first hit each brick picks a random variant index plus random X/Y renderer flips, then keeps them, so cracks differ between bricks while escalating damage reads as the same crack spreading (each heavy sprite extends its light counterpart).
- `Assets/Scripts/Debris.cs` — cosmetic rubble for a shattering brick, spawned by `Brick` at destruction (runtime-only, nothing to author in the editor). 6–9 small cube fragments share the brick's material, tinted with per-fragment brightness variation of the brick's color via `MaterialPropertyBlock`; the cube mesh is lifted once off a throwaway `CreatePrimitive` template. Fragments carry no physics components — they are moved by hand in `Update` (initial outward/upward pop, constant gravity, random tumble), so they can never disturb the 2D gameplay colliders; they shrink away over the last third of a 1.2–2 s life (the opaque Lit material can't alpha-fade) and also die below the playfield.
- `Assets/Scripts/GameManager.cs` — state machine (Menu/Ready/Playing/EnteringName/GameOver/Won), score, lives, high score persisted via `PlayerPrefs` (`Arkanoid.HighScore`), runtime brick-grid construction (per-row color and hardness: red rows take 3 hits, blue rows 1). When a round ends above the record held at round start, switches to `EnteringName`: captures the player's name via `Keyboard.onTextInput` (backspace edits, ENTER submits, 12-char cap) and appends a `RecordBook` entry. Pushes values into the `ScoreBoard` and drives the `RecordsPanel` and `MainMenuPanel`; OnGUI is only used for the "press SPACE to launch" banner. Boots into the `Menu` state (SPACE starts a game, R shows the hall of fame, ESC/R returns); end screens go back to the menu on SPACE. Serialized references are wired by the editor setup script.
- `Assets/Scripts/ScoreBoard.cs` — display-only UGUI HUD component on the `ScoreBoard` canvas (Score / High Score / Lives); `GameManager` pushes values in.
- `Assets/Scripts/RecordBook.cs` — static store for the chronological record-holder list (date/name/score), persisted in `PlayerPrefs` (`Arkanoid.Records`) as JSON.
- `Assets/Scripts/RecordsPanel.cs` — display-only end-of-round overlay under the `ScoreBoard` canvas: name entry after a new record, then the hall-of-fame list. Authored inactive; `GameManager` shows/hides it (also reused from the menu's "hall of fame" option).
- `Assets/Scripts/MainMenuPanel.cs` — display-only full-screen title overlay under the `ScoreBoard` canvas (title, high score line, key prompts). Authored inactive; `GameManager` shows it at startup and after end screens.
- `Assets/Editor/ArkanoidSetup.cs` — `[InitializeOnLoadMethod]` script that generates the sprite textures (`Assets/Sprites`), configures their importers, creates the bouncy `PhysicsMaterial2D` (`Assets/Physics`) and the `Ball`/`Brick` prefabs (`Assets/Prefabs`), then authors the camera, walls, paddle, and wired `GameManager` into the scene, and finally the `ScoreBoard` screen-space canvas. Editor-authored content stays inspectable without Play mode; only the ball and bricks exist at runtime.

## Editor setup is staged and resumable

`ArkanoidSetup.Setup()` performs **one** stage per domain reload and returns, relying on the next reload to observe the previous stage's output (textures → importers → physics material → prefabs → scene → scoreboard UI → records panel → deferred save → main menu panel → deferred save → crack texture variants → crack importers → brick-prefab crack overlay → Lit materials → ball prefab to sphere → brick prefab to box → 3D scene retrofit → deferred save → squared wall corners → deferred save → brick wall texture → textured wall materials → wall material swap → deferred save → world-UV wall meshes → wall mesh swap → deferred save → randomized-crack prefab retrofit → rounded paddle mesh → paddle mesh/collider swap → deferred save → centered light position → deferred save → centered light direction → deferred save → rounded brick mesh → brick variant prefabs → GameManager variant wiring → deferred save). The crack textures are generated from a per-variant seeded `System.Random` walk (`Assets/Sprites/CrackLight0-3.png` / `CrackHeavy0-3.png`), so a from-scratch rebuild reproduces the same set. The UI-panel stages (7 and 9) only mark the scene dirty; the follow-up stages (8 and 10) save it from a self-removing `EditorApplication.update` handler on the next editor tick, to avoid the modal dialog described below. This works around `AssetDatabase` writes not being reliably readable back via `LoadAssetAtPath` within the same call. If you touch this file, preserve the one-stage-per-reload structure. The scene stage is guarded by `GameObject.Find("GameManager")`, so once set up the whole method is a no-op.

Folder existence is checked on disk (`System.IO.Directory`) rather than via `AssetDatabase.IsValidFolder`, which can go stale in driven sessions.

**Caution:** the scene stage calls `EditorSceneManager.SaveScene` from `[InitializeOnLoadMethod]`; in one session Unity then detected the open scene's file change and raised a *modal* "scene changed on disk" dialog that blocked the Editor main thread (and the Uplink bridge) until dismissed by hand. Either button is safe (disk and memory content are identical), but be aware programmatic scene saves can trigger it.

Use the `unity-game-design` skill for the general pattern this file follows when making further Editor-script changes here.
